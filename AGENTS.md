# AGENTS.md - Working in `app/`

## Quick Rules

- `app/styled-system/` is generated by Panda. Do not edit by hand.
- Dependency installs are user-run by default: run `pnpm i` yourself when dependencies change or a package is added/updated.
- Assume sandboxed installs may fail; treat local user install as the reliable path.
- AI SDK/OpenAI env setup is documented in `app/.env.example`. Provide `OPENAI_API_KEY`; prefer `OPENAI_MODEL=gpt-5-mini` and `OPENAI_HEAVY_MODEL=gpt-5.4`.
- Reads: `query()` + `createResource()`.
- For `createResource`, prefer `resource.latest` for steady UI during revalidation.
- Use `resource()` directly only when you intentionally need loading/pending-state transitions.
- Writes: server actions.
- Avoid `fetch()` in UI components for app data.
- Prefer `~/components/ui/*` wrappers over ad-hoc route-local composition.
- Keep reusable UI out of `app/src/routes/`.
- Aim for roughly `200-300` LOC per file you create or substantially expand.
- If code you are writing is trending beyond that range, proactively refactor it into smaller modules/components/helpers before it exceeds the limit instead of leaving an oversized file behind.

## Prototype Verification

- This is a prototype; conserve tokens and avoid routine browser automation unless the user explicitly asks for it.
- Only run Playwright MCP, in-browser tools, screenshots, or browser-driven QA when the prompt specifically requires them.
- Save Playwright screenshots, visual diffs, and other test images under repo-root `./tmp/` so they stay out of version control.
- Only add or run tests when the user asks for tests, the task is explicitly test-focused, or the change is risky enough that skipping tests would leave an important behavior unverified.
- For ordinary prototype edits, use targeted code review and lightweight checks instead of defaulting to full browser/test passes.

## UI Conventions

- Prefer simplified shared wrappers when they fit:
  - `SimpleDialog`
  - `SimplePopover`
  - `SimpleSelect`
  - `PanelPopover`
  - `ConfirmDialog`
- Use `ClearButton` and `CloseButton` for icon-only clear/close actions.
- Keep SSR + hydration output stable for overlay controls.
- Use Panda tokens and recipes; avoid hard-coded spacing/colors unless a token is missing.
- For selected/current items in menus, dropdowns, lists, and inspectors, prefer a subtle background fill plus text treatment. Do not add decorative left/right accent bars, inset side borders, or stripe markers unless the component is explicitly a navigation rail or timeline.

## Spatial Map Canvas Safety

- The spatial map canvas renders a scaled SVG scene. Do not add CSS/SVG filters, `drop-shadow()`, `blur()`, or `filter` transitions to `.spatial-map-scene-layer`, `.spatial-map-node`, or child elements inside the scaled canvas.
- Avoid `will-change: transform`, `transform: translateZ(0)`, and similar forced-compositing hints on the scaled SVG scene or nodes. At high zoom these have repeatedly caused flicker, oversized raster surfaces, and visual smearing.
- If emphasis is needed on canvas nodes, prefer SVG-safe strokes, fills, opacity, or small unfiltered geometry changes instead of filter/shadow effects.

## Data + SSR Safety

- Keep server-only logic on the server.
- Keep component render trees deterministic between server and first client render.
- For wrappers, ensure external props are forwarded to the actual rendered slot.

## Router Actions + Writes

- For UI-triggered writes, prefer `useAction(...)` in TypeScript over `<form method="post">` submissions.
- Avoid adding new form-backed mutations unless native browser form behavior is explicitly required and worth the extra transport/state complexity.
- Keep write state local and explicit with signals such as `pending`, `error`, and optimistic values instead of relying on `useSubmission()` or `useSubmissions()`.
- Build `FormData` in TypeScript only when an existing server action still expects it. Do not render hidden forms or call `requestSubmit()` as an action transport.
- For new or substantially touched actions, prefer typed object inputs over `FormData` when Solid Router/server-action constraints allow it.
- Keep action handlers stable and named, and keep server-only logic on the server.
- Avoid `normalizeActionUrl(...)` in new UI code; it exists for legacy form-backed actions during migration.
- Treat “button click does nothing” on an action flow as a likely client/action-state issue first. Verify the relevant `useAction(...)` call runs, pending state changes, and errors surface in UI/toasts.

## AI SDK + Structured Data

- The app package includes `ai`, `@ai-sdk/openai`, and `zod`.
- Keep OpenAI usage in server-only code paths and read secrets from `process.env.OPENAI_API_KEY`.
- Default to `gpt-5-mini`; use `gpt-5.4` for heavier reasoning only when the task warrants it.
- Prefer `generateText()`/`streamText()` with `Output.object({ schema })` over older `generateObject()`/`streamObject()` examples in new code.
- Define narrow `zod` schemas close to the server module that owns the contract and return typed objects across the server boundary instead of raw JSON strings.
